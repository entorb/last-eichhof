# The Last Eichhof - Rewrite

Rewrite of the 1993 MS-DOS game **The Last Eichhof** in modern web tech stack

Tech stack: phaser V4, vite, typescript, pnpm

## Instructions

- New game shall be close to original, but not 100%. Improve what is odd
- Use context7 for latest phaser v4 features
- Use American English, not British
- Update AGENTS.md after a research, so future ai coding is more efficient
- Use `./tmp/` instead of `./tmp/` for debugging scripts

## References

- Wikipedia info about the original game is in [wiki.md](docs/wiki.md).
- Source code of original DOS game is at `beer_src/` (not committed). An overview of the files is in [beer_src](docs/beer_src.md).
- Compiled original DOS game, including the graphics and sound, is at (`beer_exe/`) (`BEER.DAT` = `ALPHA-HELIX COMBINER VER 3.3` archive; parse the directory at offset 34: `name[14] size(4) flags(2) fptr(4)`, data starts right after the directory)
- How to decode graphics and sound out of `BEER.DAT` (archive layout, `.SLI` sprites, palette, animation timing, enemy mapping, `.SND` samples): [docs/beer_dat.md](docs/beer_dat.md)

## Browser Debugging

`playwright-core` is a dev dependency (no browser bundled). Install the matching Chromium once: `pnpm exec playwright-core install chromium` (add `webkit` if needed); browsers land in `~/Library/Caches/ms-playwright` and are versioned to the installed `playwright-core`.

For a manual end-to-end check, put a throwaway script in `./tmp/*.mjs` (gitignored; it resolves `playwright-core` from the root `node_modules`), start `pnpm dev` (URL is `http://localhost:8080/last-eichhof/` — the vite `base`), and drive the game:

```js
import { chromium } from "playwright-core";
const browser = await chromium.launch();
const page = await browser.newPage();
page.on("pageerror", (e) => console.error(e)); // Phaser errors surface here
await page.goto("http://localhost:8080/last-eichhof/", { waitUntil: "load" });
await page.waitForTimeout(2500);
// Reach into a scene: TS `private` is not runtime-private.
const state = await page.evaluate(() => {
  const s = window.__game.scene.getScene("Game"); // dev-only handle
  return { state: s.state, lives: s.lives };
});
await browser.close();
```

- `src/main.ts` exposes `window.__game` only when `import.meta.env.DEV` (stripped from `pnpm run build`). Use it to force states (`s.playerHit()`, `s.bossesLeft = 0`, `s.reward...`), read `s.state`/`s.lives`/`s.message.text`, and screenshot with `page.screenshot()`.
- Mobile: `browser.newContext({ viewport: { width: 800, height: 360 }, deviceScaleFactor: 2, isMobile: true, hasTouch: true })`; use `page.touchscreen.tap(x, y)` (logical→screen `x*0.5`, `y*0.5` for the 960×720 canvas) and CDP `Input.dispatchTouchEvent` for held drags. This is how the mobile death/black-screen bug was reproduced.
- Not wired into `pnpm test`; run it manually when a bug needs a real browser (touch input, scene transitions, rendering).

## Coding Notes

- Phaser `Input.Keyboard` key types are `Phaser.Types.Input.Keyboard.*` (e.g. `CursorKeys`), not `Phaser.Input.Keyboard.*`.
- `this.input.keyboard` is nullable; guard before use (`if (!kb) throw ...`).
- Mobile/touch input lives in `src/game/input/`: `controls.ts` is pure (`resolveTouchControls(mode, deviceTouch)`, `moveVector(keys, stick)` — sums keyboard + analog stick and clamps to unit length; self-check + vitest) and `touchpad.ts` is the on-screen d-pad + OK/ESC for `Menu`/`Shop` (poll once per frame: `pad.poll()` returns the pressed actions and clears them). `Settings.controls` (`"auto" | "touch" | "keyboard"`, default `"auto"`, no longer in the OPTIONS menu — always `"auto"` unless set directly) picks touch; `AUTO` follows `this.sys.game.device.input.touch`. `Game`, `Menu` and `Shop` read it in `create()`.
- Touch mode in `Game`: floating joystick from `phaser4-rex-plugins` (`VirtualJoyStick`), plus auto-fire (`fire()` bails only when neither `keyFire.isDown` nor `touch`), a pause button, and tap-to-continue on game over. Two non-obvious gotchas: an `alpha: 0` sprite is skipped by input (`setAlpha(0)` clears the render flag), so the plugin base is an invisible interactive `Zone`; and `InputPlugin.enable` early-returns when an object already has input, so widening the hit area needs `base.removeInteractive()` **then** `setInteractive(...)`. Recenter zone/ring/thumb on `pointerover` **and** `pointerdown` (Phaser can fire over first) with listeners registered before the plugin's.
- Landscape is enforced by CSS only: `index.html` has a `#rotate` overlay shown by `@media (orientation: portrait)` in `public/style.css`; the viewport meta disables zoom and `#app canvas { touch-action: none }`. `main.ts` sets `input.activePointers: 3` for simultaneous joystick + buttons.
- Fullscreen toggle lives in `src/game/input/fullscreen.ts`: `toggleFullscreen(scene)` only (no separate button; `createFullscreenButton` was removed). It is a native menu entry (`Menu.rebuild` builds a `fullscreenEntry` `Item` with a dynamic `FULLSCREEN`/`EXIT FULLSCREEN` label), inserted above `OPTIONS` on the start screen and last in the pause overlay; it is omitted entirely when `scale.fullscreen.available` is false (iPhone Safari) so there is never a dead entry. The entry sets `Item.pointerUp: true` so `addItems` binds `pointerup` instead of `pointerdown` — fullscreen requests must come from a user gesture and mobile browsers reject `pointerdown`. `Menu` re-renders on `Scale.Events.ENTER_FULLSCREEN`/`LEAVE_FULLSCREEN` to flip the label. `main.ts` sets `fullscreenTarget: "app"` so the `#app` container (canvas + `#rotate` overlay) goes fullscreen instead of Phaser wrapping the canvas in its own div.
- Audio is both sampled and synthesized. Extracted original DOS samples (`public/assets/sounds/*.ogg`, manifest `src/game/data/sounds.ts`) play through `Samples` (wraps Phaser's sound manager: `play`/`loop`/`setLevel`); `Synth` keeps Web Audio fallbacks where the original has none (player laser, hit, UI blips), and `Music` plays the `TITLE`/`GAME` synth patterns for menu/scores/game (the original `TITLE.SND`/`HS.SND` are copyright-protected, so `scripts/extract-sounds.mjs` skips them and the two OGGs are `.gitignore`d — do not re-add them). `Sound` is a namespace export; guard `manager instanceof Sound.WebAudioSoundManager` and use `manager.context`/`.destination`. `Samples`/`Synth`/`Music` no-op when the manager is HTML5/NoAudio.
- Web Audio context starts suspended; `Music.tick` must bail while `!synth.running` and resync `nextTime` when it lags `ctx.currentTime` (first gesture unlocks playback).
- Vite 8 / rolldown requires `build.rollupOptions.output.manualChunks` as a **function**, not an object map.
- `base` in `vite/config.*.mjs` must match the deploy directory (`scripts/deploy.sh` rsync to `html/last-eichhof/`, so base is `/last-eichhof/`). A mismatch makes the built CSS/JS 404, which leaves the raw `#rotate` overlay visible and the game blank.
- `vite/config.prod.mjs` sets `build.outDir: "../dist"`: vite's `root` is `src`, so the default `dist` would land in `src/dist` (untracked, unlinted, and not what `scripts/deploy.sh` rsyncs). Keep it pointed at the repo-root `dist` that `.gitignore` ignores.
- Pure logic also gets a `runSelfCheck()`/`run*SelfCheck()` (assert-based) called from `Boot.create()`; keep it passing (vitest cannot reach the Phaser scenes).
- `biome check --write` may reorder imports; run it before `tsc`/`build`.
- `ScenePlugin.restart()`/`start()` with no data keep the previous scene data; pass explicit data (`restart({ pause: false })`) to reset `init()`.
- Scenes render in config-list order (`[Boot, Menu, Shop, Game]`), so `Game` draws **over** an overlay launched with `scene.launch("Menu")`; call `scene.bringToTop("Menu")` when launching the pause overlay or it stays hidden behind the game.
- Phaser 4 removed the `setTintFill(color)` argument: use `setTint(color).setTintMode(TintModes.FILL)` (import `TintModes` from `phaser`).
- `Menu` and `Shop` treat Enter and Space as the same confirm key; keep both wired when adding menus. Menu/Shop list items are also pointer-clickable (`setInteractive` + `pointerdown` → `activateItem(i)`, which selects, plays the confirm sound and activates); selection is shown by color only, no `>` prefix. `Menu`'s score tabs and footer (back) are clickable too, as is the `Game` game-over `pointerdown`.
- Enemy/ship/explosion art and the per-level enemy rosters are extracted from `beer_exe/BEER.DAT` by `node scripts/extract-sprites.mjs` (see [docs/beer_dat.md](docs/beer_dat.md)). It writes `public/assets/enemies/<key>.png` (horizontal animation strips, 3× nearest-neighbor) + a `contact.html` sheet, and regenerates `src/game/data/enemySprites.ts` (`SPRITE_SHEETS`) and `src/game/data/foeRosters.ts` (`FoeKind`/`FOES`/`ROSTERS`). Never hand-edit those generated files — edit `scripts/enemy-map.json` or the DOS data and re-run. `enemy-map.json` also has a `weaponSprites` map (`<weapon id>` → `WEAPONS.SLI` sprite index) which emits the shop weapons as `wpn-<id>` sheets (9 of the 14; the 5 web-only weapons keep procedural icons — `Boot`/`vectorArt` skip ids already in `SPRITE_SHEETS`). `Boot.preload()` loads each sheet via `load.spritesheet`; `Boot.create()` registers an anim per sheet (`repeat: -1`, except `explosion` which is `repeat: 0`). Phaser `GameObjects.Sprite` is not a subclass of `GameObjects.Image`; animated objects (ship, enemies, explosions, weapon mounts) must be typed/created as `Sprite` (`add.sprite`), and `overlap()` takes `Image | Sprite`.
- Original sound FX/music are extracted from `beer_exe/BEER.DAT` by `node scripts/extract-sounds.mjs` (see [docs/beer_dat.md](docs/beer_dat.md)). It decodes `.SND` (single `sndstrc` or library; 8-bit PCM or 4-bit Creative ADPCM `0x75`), encodes OGG Vorbis via `ffmpeg-static`, writes `public/assets/sounds/<key>.ogg` + `audition.html`, and regenerates `src/game/data/sounds.ts` (`SOUNDS` manifest + `LEVEL_CUES`). Never hand-edit `sounds.ts` — re-run the script. `Boot.preload()` loads every manifest entry with `load.audio`; `Samples` maps game events to keys (`enemyShot`/`explosion`/`bossExplosion`/`cue` are per-level from `LEVEL_CUES`). `biome` ignores the generated `audition.html`.
- Two graphics skins: `Settings.graphics` (`"retro"` default | `"modern"`), cycled in `Menu` OPTIONS. `skinKey(key, mode)` (`src/game/data/skins.ts`) prefixes `v-` for modern; use it for **every** texture and animation key (ship, enemies, `explosion`, `cork`, `pellet`, `stars-*`, `wpn-<id>`), plus `bgKey(level)` for backgrounds. Retro = extracted PNGs; modern = `src/game/art/vectorArt.ts` rebuilds each `SPRITE_SHEETS` entry from its own retro texture in `Boot.create()`: down/up-scale for smooth edges, then a per-sprite duotone recolor (hue from the sprite's average color, level accent when grey) plus a bright rim, into `textures.createCanvas` with `texture.add(f, ...)` per frame so `generateFrameNumbers`/anims work. Silhouettes stay recognisable; only `cork`/`pellet`/`stars-*`/the 5 web-only `wpn-<id>` icons/`bg-*` are drawn procedurally. Both skins are always generated, so switching applies on the next `Game`/`Shop`/`Menu` create (no reload). Add new art to both or the Boot existence check throws.
- `CanvasTexture` frames: `createCanvas` gives only `__BASE`; call `tex.add(name, 0, x, y, w, h)` for each frame and `tex.refresh()`. The first added frame becomes `firstFrame`, so a frame-less `add.image`/`add.sprite` shows frame 0 (not the whole atlas).
- SonarCloud findings are pulled into `tmp/sonar.json`; fix every issue. Recurring rules:
  - `Number.parseInt`/`Number.parseFloat` over the globals (`S7773`); prefer `for...of` over an index `for` when the index is unused (`S4138`).
  - `String#codePointAt` over `charCodeAt` (`S7758`).
  - Mark fields only assigned in the constructor `readonly` (`S2933`) — includes constructor parameter properties (`private readonly synth: Synth`).
  - No nested ternaries (`S3358`); use `if`/`else` or a `switch`. Clamps use `Math.min`/`Math.max` (`S7766`).
  - Membership tests use a `Set` + `.has()`, not `Array#includes` (`S7776`).
  - Don't wrap a promise chain in `try` when `.catch()` already handles rejection (`S4822`); guard a possibly-missing global with `globalThis.fetch?.(...)` (optional chaining short-circuits the whole chain).
  - `.sonarcloud.properties` holds `sonar.exclusions` (generated files) and `sonar.issue.ignore.multicriteria` for intentional deviations: `Web:S7926` (viewport `user-scalable=no`) is ignored for `src/index.html` because this is a fixed landscape canvas game where browser zoom breaks layout and input mapping. Add new suppressions there with a comment explaining why — never inline `NOSONAR`.

## Architecture

| Area           | Where / what                                                                 |
|----------------|------------------------------------------------------------------------------|
| Scenes         | `src/game/scenes/`: `Boot` (textures + self-checks → `Menu`), `Menu` (title/options/scores/pause; scores mode has `TOP 10`/`HISTORY` tabs — left/right switches, up/down scrolls the history window via `clampScroll`, Enter/Esc exits; the start screen footer has inline link groups — `Original DOS game: Download SourceCode Wikipedia` and `New code: GitHub` — where each link is its own item so only the highlighted word turns gold, plus "Global Games Played"), `Game` (gameplay), `Shop` (between levels; modes `shop` root categories → `weapons`/`upgrades`/`sell` submenus, `place`; ESC in a submenu returns to root, ESC in root continues) |
| Level data     | `src/game/data/level1.ts`: `PLAY {w:960,h:720,hud:48}`, `PathRunner`, `pathFor(kind)`, re-exports generated `FOES`/`FoeKind` (shared types/machinery) |
| Levels         | `src/game/data/levels.ts`: `LEVELS[5]` built from generated `ROSTERS` (`{n,name,bg,starTint,bossHp,shieldBonus,bosses,checkpoints,scoreScale,build()}`), `getLevel(n)`, `runLevelsSelfCheck()`. `scoreScale` is a hand-written balance layer (`Game.spawnEnemy` stores `Math.round(spec.score * level.scoreScale)`): level 1 is the "EASY START" tutorial whose end boss loops and spawns 13×, so its kills are scaled to 0.3 to keep it below every later level (asserted in `levels.test.ts`) |
| Rosters        | `src/game/data/foeRosters.ts` (generated): web level *n* = DOS `LEVEL{n-1}`; one `FoeKind` (`l{level}-f{foe}`) per referenced non-projectile `.FOE` entry, shared texture `l{level}-s{sprite}`; `FOES[kind].path` is the replayed DOS `.FOE` path; `ROSTERS` carries the DOS `.TBL` spawn schedule (`at`=frames/20, coords ×3), `MARK` checkpoints, boss count and derived `bossHp` |
| Weapons        | `src/game/data/weapons.ts`: `WEAPONS` (14: lager starter + pony/stange/can33/vshot/humpe/dunkel/pokal/barbara/seite/chuebeli/kanone/reflect/homing; emitter lists + `period`/`power`/`kind`, `w`/`h` = real sprite footprint), `UPGRADES`, `moneyForLevel`, `GRID=12` (DOS 4 px ×3), `snap`/`canPlace`, `runWeaponsSelfCheck()` (also asserts `w`/`h` match the extracted `wpn-<id>` sheet) |
| Run state      | `src/game/data/run.ts`: in-memory `Run` (level, money, score, lives, speedUps, loadout); `newRun`/`getRun`/`endRun`/`shipSpeed` |
| Persistence    | `src/game/data/store.ts`: settings + results in `localStorage` (`eichhof.settings`, `eichhof.results`), all wrapped in try/catch |
| Scene flow     | `src/game/flow.ts` holds every transition as a pure function taking a `SceneSwitcher` (the scenes pass `this.scene`; tests pass a recorder): `startNewGame`/`pauseGame`/`resumeGame`/`quitToMenu`/`finishLevel`/`endGame`/`continueToNextLevel`. `Boot → Menu → Game ⇄ Shop → Menu`; win levels 1–4 → `Shop`, win level 5 → `Menu` (game complete), game-over/quit → `Menu`. `Menu` START GAME calls `newRun()` so a new game always starts at score 0; `Shop → Game` reuses the in-progress run. Every `start("Menu")` from `flow.ts` passes `{ pause: false }`: a bare `start` reuses the previous Menu data, so after a pause overlay (`{ pause: true }`) a game-over would reopen the Menu in pause mode over a stopped Game (black screen) |
| Difficulty     | `DIFFICULTY` in `store.ts`: easy/normal/hard → lives 5/4/3, foe speed 0.85/1/1.2 (lives seed `newRun`) |
| Mobile input   | `src/game/input/`: `controls.ts` (`resolveTouchControls`, `moveVector`; pure, self-checked, tested) + `touchpad.ts` (on-screen d-pad for `Menu`/`Shop`). `Game` adds a floating `phaser4-rex-plugins` `VirtualJoyStick` (invisible `Zone` base) + auto-fire + pause button; `Shop` place mode is drag-to-position. `Settings.controls` (auto/touch/keyboard, not exposed in OPTIONS) selects it; `Settings.autoFire` (OPTIONS `AUTO-FIRE`, default off) makes the ship fire without holding SPACE (touch always fires); landscape-only via the CSS `#rotate` overlay |
| Enemy art      | `scripts/extract-sprites.mjs` → `public/assets/enemies/<key>.png` (original DOS sprites, 3×) and generated `src/game/data/enemySprites.ts` (`SPRITE_SHEETS`) + `src/game/data/foeRosters.ts`; `Boot` loads/animates them. `WEAPONS.SLI` also yields the `wpn-<id>` mount sheets (see `enemy-map.json` `weaponSprites`). Procedural in `Boot`: `cork`, `pellet`, `stars-far/near`, the 5 web-only `wpn-<id>` icons. `contact.html` is a dev aid |
| Audio          | `src/game/audio/`: `Samples` (plays extracted original `.ogg`s through Phaser's sound manager; `setLevel`), `Synth` (Web Audio SFX + fallbacks), `Music` (synth `TITLE` menu/scores + `GAME` pattern; original `title`/`hs` samples are not shipped), singleton `initAudio`/`getSfx`/`getMusic`/`getSamples`; `runAudioSelfCheck()`/`runSoundsSelfCheck()` in `Boot` |
| Sound          | `scripts/extract-sounds.mjs` → `public/assets/sounds/<key>.ogg` (original DOS samples, OGG Vorbis) + generated `src/game/data/sounds.ts` (`SOUNDS`, `LEVEL_CUES`); `Boot` loads them, `Samples` plays them (`buy`/`sell` shop loops, `go`/`tod`, per-level `enemyShot`/`explosion`/`bossExplosion`/`cue`). Original `TITLE.SND`/`HS.SND` are copyright-protected and intentionally not shipped (`.gitignore`d) — menu/scores music is synth. `audition.html` is a dev aid |

- HUD occupies top `PLAY.hud` (48px); play area is below it.
- Game states: `shield → play → dead → win | gameover`; `ESC` pauses (`scene.pause`) and launches `Menu` with `{ pause: true }` (RESUME / QUIT TO MENU; quit calls `Game.abortGame()` to record the score and `endRun()`).
- Music is scene-driven via `getMusic().setScene("menu"|"scores"|"game"|"shop")`; menu/scores always use the synth `TITLE` pattern (original samples not shipped); `resumeGame()` restores game music. `Shop` calls `setScene("shop")` (stops the `GAME` synth) then loops `buy`/`sell` samples. `Boot` sets `sound.volume = 0.8`.
- Weapons fire simultaneously from the run loadout, each on its own `period` cooldown; shots carry `power`, plus `homing`/`reflect` behaviors.
- `Emitter.release` (`weapons.ts`) spawns sub-shots mid-flight (`after` seconds) at the parent's position with the parent tint; `Game.releaseShots()` fires once and clears the release. Pokal bursts into 4 diagonals, Pony Reflector releases a second bouncing shot.
- `PathRunner` (`level1.ts`) path commands: `go`/`line`/`home`/`wait`/`mark`/`loop`/`cycle(times)`/`spawn(kind)`/`sprite(texture)`/`release(kind,x,y)`/`shot(speed)`. `spawn`/`sprite`/`release`/`shot` are instantaneous and pushed to `runner.events`; `Game.updateEnemies` drains them. `mark` also records the position and `loop`/`cycle` reset `pos` to it (DOS `CYCLE` returns the object to the `MARK` position). Foe flags `invincible` (blocks but unharmed) / `transparent` (shots pass through) live on `FoeSpec` and are honored in `Game.collide()`.
- Enemy movement is **the original DOS path**, not an archetype. `FOES[kind].path` is generated by `scripts/extract-sprites.mjs` from each `.FOE` path: runs of identical `(dx,dy)` frames merge into one `go` (coords ×3, `speed = |delta|*60` web px/s so one 20 Hz frame is preserved), plus `mark`/`loop`/`sprite`/`release`/`shot`. `pathFor(kind)` (`level1.ts`) returns that real path for **every** foe with one — bosses, minibosses and `invincible`/`transparent` foes included (e.g. level 2's invincible miniboss `l1-f34` must still descend/release/retreat, not take the generic exit). The `weave`/`diver`/`zig`/`miniboss`/`boss`/`EXIT_PATH` archetypes remain only as a fallback for foes without a path. `Game.updateEnemies` destroys any foe whose path hits `END` (DOS `0x8000`); if it was a scheduled boss that reaches `END` un-killed it also decrements `bossesLeft`. Bosses are detected by `FOES[kind].role`, never by the string `"boss"`.
- Enemy fire **is** in the paths: a `RELEASE` (`0x8002`) whose target is a `FOE_LINE` (`0x20`) foe becomes a `shot(speed)` event; one whose target is a fightable minion becomes a `release(kind,x,y)` event. Both fire exactly when the path reaches the command and repeat on `loop`. Only schedule-spawned foes release minions (`Enemy.scheduled`) so the release graph cannot chain. `Game.spawnEnemyShot(x,y,speed)` mirrors DOS line mode: aim at the ship's position at release, velocity `speed*60` web px/s on the dominant axis (covers `max(|dx|,|dy|)` in `max/speed` ticks); the `pellet` texture is used as-is. Level 1 has no shooters; levels 2–5 are shot-heavy.
- Attack table (`Spawn.cmd`): generated `ROSTERS[].spawns` already interleave `.TBL` commands (`fieldOn`/`fieldOff`/`mark`) with foe spawns in one sorted queue. `Game.spawnWaves` toggles starfield scrolling (`fieldOn`) / stores a marker (no-op in the flat schedule). Use `fieldOff` before a boss and `fieldOn` shortly after.
- Paths are authored in DOS space and stay inside the play area (spawn coords are `.TBL` ×3, deltas ×3, so the original on-screen envelope is preserved). The DOS status bar sat at the **bottom** (`BARY`), so DOS `y=0` is the play-area top; the web HUD is at the top, so `Game.spawnWaves` adds `TOP` (`PLAY.hud`) to every spawn y. Without it, top-hovering bosses park behind the HUD (level 2's `l1-f37`). Off-screen culling uses the same envelope `levels.ts` asserts (`x < -PLAY.w` / `x > PLAY.w*2`), so foes that start just off-screen still fly in. Path-`END` destroys any foe (scheduled bosses decrement `bossesLeft`), and `checkWin` only needs `bossesLeft`, so a looping/un-killable foe can never soft-lock.
- Boss count is per level from the generated `ROSTERS` (`LevelDef.bosses`): `Game` tracks `bossesLeft` (not a bool) and wins on `bossesLeft <= 0` (DOS `nbigboss == 0`), even if released minions/chaff are still alive. All checkpoints sit before the first boss; on rewind `bossesLeft` is recomputed as bosses with `at > t` (they all re-spawn).
- Debug keys in `Game`: `J` jumps to the next checkpoint, or (once all are passed) to the boss and respawns it if missing; `G` toggles god mode (one-hit-kill enemies + money + player invulnerable). `oneHitKill` lives on the persistent scene instance, so god mode (and its `GOD MODE` text, re-shown from `create`) survives level transitions until toggled off.
- Game feel (`Game.ts`): original `explosion` spritesheet animation (`spawnExplosion` plays the `explosion` anim once, `updateExplosions` fades it), white hit-flash on non-lethal enemy hits (`hitFlash` + `TintModes.FILL`), `cameras.main.shake` on player/boss hit, and alpha blink during the `shield` invincibility window.
- The HUD shows liters/level/lives; bottom-left shows the ship + a row of `wpn-<id>` loadout icons (no weapon names). Bought weapons are also mounted next to the ship (`Game.buildMounts`/`updateMounts`, skipping the starter lager = the ship itself), tracked to the ship each frame and hidden on death. Shop placement and the HUD/mounts all use the same `wpn-<id>` textures.
- Shop placement mirrors the DOS shop: the `wpn-<id>` sprite is drawn at native 3× size inside the 360×240 area, moved on the `GRID` (12 = DOS 4 px ×3) and kept inside with a 12 px margin; overlap uses the real footprints (`Weapon.w`/`h`) like DOS `crashtest`. The buy/sell lists show the weapon sprites next to the labels (`Shop.Item.icon`).
- Each level has a distinct background colour + star tint; foe shields get `shieldBonus` and the boss gets `bossHp` from its `LevelDef`. `won` in results is true only on finishing level 5.
- Levels 2–5 define `checkpoints: number[]` (seconds, before the boss spawn). On death the game rewinds `levelTime`/`spawnIndex` to the last passed checkpoint and clears live enemies/shots; level 1 has none, so it continues in place. Self-check asserts checkpoints are sorted and pre-boss.
- Original DOS enemy fire = `FOERELEASEFOE` (`0x8002`) in a `.FOE` path, spawning a `FOE_LINE` (`0x20`) bullet (speed = that entry's `speed`) or a path foe (minion) at the parent position; the extractor replays it as a `shot`/`release` path event. `.FOE` layout: `n(2)` + packed far ptrs (unswizzle `((v>>12)&0xffff0)|(v&0xf)`, +2 base) + `foestrc {flags,shield,score,expl,sprite,speed,path[]}`; path commands `0x8000 END`, `0x8001 SPRITE(+1 word)`, `0x8002 RELEASE(+3 words)`, `0x8004 CYCLE`, `0x8005 MARK`, `0x8006 SOUND(+1 word)`, else a `(dx,dy)` pair = 1 frame @20 Hz. `LEVEL0..4` = levels 1..5; LEVEL0 (level 1) spawns no shooters, levels 2–5 are shot-heavy.
