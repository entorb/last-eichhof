# The Last Eichhof - Remake

Remake of the 1993 MS-DOS game **The Last Eichhof** in modern web tech stack

Tech stack: phaser V4, vite, typescript, pnpm

## Instructions

- New game shall be close to original, but not 100%. Improve what is odd
- Use context7 for latest phaser v4 features
- Use American English, not British
- Update AGENTS.md after a research, so future ai coding is more efficient
- Use `./tmp/` instead of `/tmp/` for debugging scripts

## References

- Wikipedia info about the original game is in [wiki.md](docs/wiki.md).
- Source code of original DOS game is at `original_game/beer_src/` (not committed). An overview of the files is in [original_game/beer_src](docs/beer_src.md).
- Compiled original DOS game, including the graphics and sound, is at (`original_game/beer_exe/`) (`BEER.DAT` = `ALPHA-HELIX COMBINER VER 3.3` archive; parse the directory at offset 34: `name[14] size(4) flags(2) fptr(4)`, data starts right after the directory)
- How to decode graphics and sound out of `BEER.DAT` (archive layout, `.SLI` sprites, palette, animation timing, enemy mapping, `.SND` samples): [docs/beer_dat.md](docs/beer_dat.md)

## Browser Debugging

`playwright-core` is a dev dependency (no browser bundled). Install the matching Chromium once: `pnpm exec playwright-core install chromium` (add `webkit` if needed); browsers land in `~/Library/Caches/ms-playwright` and are versioned to the installed `playwright-core`.

For a manual end-to-end check, put a throwaway script in `./tmp/*.mjs` (gitignored; it resolves `playwright-core` from the root `node_modules`), start `pnpm dev` (URL is `http://localhost:8080/last-eichhof/` — the vite `base`), and drive the game:

```js
import { chromium } from "playwright-core";
const browser = await chromium.launch();
const page = await browser.newPage();
page.on("pageerror", (e) => console.error(e)); // Phaser errors surface here
await page.goto("http://localhost:5173/last-eichhof/", { waitUntil: "load" });
await page.waitForTimeout(2500);
// Reach into a scene: TS `private` is not runtime-private.
const state = await page.evaluate(() => {
  const s = window.__game.scene.getScene("Game"); // dev-only handle
  return { state: s.state, lives: s.lives };
});
await browser.close();
```

- `src/main.ts` exposes `window.__game` only when `import.meta.env.DEV` (stripped from `pnpm run build`). Use it to force states (`s.playerHit()`, `s.bossesLeft = 0`, `s.reward...`), read `s.state`/`s.lives`/`s.message.text`, and screenshot with `page.screenshot()`.
- Mobile: `browser.newContext({ viewport: { width: 800, height: 360 }, deviceScaleFactor: 2, isMobile: true, hasTouch: true })`; use `page.touchscreen.tap(x, y)` (logical→screen `x*0.5`, `y*0.5` for the 960×720 canvas) and CDP `Input.dispatchTouchEvent` for held drags. This is how the mobile death/black-screen bug was reproduced.
- Not wired into `pnpm test`; run it manually when a bug needs a real browser (touch input, scene transitions, rendering).
- Chromium may already be at a system path — `node node_modules/playwright-core/cli.js install chromium` works when the `pnpm exec` shim is not on `PATH` (`ERR_PNPM_RECURSIVE_EXEC_FIRST_FAIL`).
- `localStorage` is unreadable on `about:blank`: `page.goto(URL)` **first**, then set the settings blob, then `page.reload()`.
- Two `page.keyboard.press` calls in the same tick land in one game frame, so a `Menu` cursor moves once instead of twice. Put ~200-300 ms between presses when driving row-based menus.
- `page.screenshot` stalls the render loop, so a following `evaluate` sees the sim advance several capped `dt` steps (a 0.5 s one-shot animation is already over). Sample animation frames from the source canvas, not the live scene.
- Phaser 4's `scale.displayScale` is not the FIT ratio; map game px to page px with `canvas.getBoundingClientRect()` and `rect.width / 960` when screenshotting a specific game coordinate.
- Art review: `/last-eichhof/skins.html` lists every sheet's DOS PNG beside the modern art (see "Coding Notes"). `tmp/contact.mjs` renders the same thing to a PNG grid when a screenshot is easier to read than the page.

## Coding Notes

- Phaser `Input.Keyboard` key types are `Phaser.Types.Input.Keyboard.*` (e.g. `CursorKeys`), not `Phaser.Input.Keyboard.*`.
- `this.input.keyboard` is nullable; guard before use (`if (!kb) throw ...`).
- Mobile/touch input lives in `src/game/input/`: `controls.ts` is pure (`resolveTouchControls(mode, deviceTouch)`, `moveVector(keys, stick)` — sums keyboard + analog stick and clamps to unit length; `stickFromForce(fx, fy, radius)` normalizes a force in game px to an 8-dir stick; self-check + vitest), `touchpad.ts` is the on-screen d-pad + OK/ESC for `Menu`/`Shop` (poll once per frame: `pad.poll()` returns the pressed actions and clears them), and `edgeStick.ts` is the off-canvas steering stick (see below). `Settings.controls` (`"auto" | "touch" | "keyboard"`, default `"auto"`, no longer in the OPTIONS menu — always `"auto"` unless set directly) picks touch; `AUTO` follows `this.sys.game.device.input.touch`. `Game`, `Menu` and `Shop` read it in `create()`.
- Touch mode in `Game`: floating joystick from `phaser4-rex-plugins` (`VirtualJoyStick`), plus auto-fire (`fire()` bails only when neither `keyFire.isDown` nor `touch`), the top-left `MENU` button, and tap-to-continue on game over. Two non-obvious gotchas: an `alpha: 0` sprite is skipped by input (`setAlpha(0)` clears the render flag), so the plugin base is an invisible interactive `Zone`; and `InputPlugin.enable` early-returns when an object already has input, so widening the hit area needs `base.removeInteractive()` **then** `setInteractive(...)`. Recenter zone/ring/thumb on `pointerover` **and** `pointerdown` (Phaser can fire over first) with listeners registered before the plugin's.
- Off-canvas steering (`src/game/input/edgeStick.ts`): the fixed 960×720 canvas sits in a letterbox inside `#app`, so on wide landscape phones the side strips are empty DOM area **Phaser never receives input on** (its listeners are on the canvas; the rex `VirtualJoyStick` also needs a Phaser pointer with a camera below it, which off-canvas coords don't have). `EdgeStick` therefore uses raw `window` `pointerdown/move/up/cancel` (skip targets that are the canvas or inside `#rotate`), `setPointerCapture` so a drag onto the canvas can't also start the plugin mid-gesture, and converts the drag delta to game px with `scale.displayScale`. `Game.moveShip` sums joystick + edge forces then `stickFromForce`. `Game` also routes an off-canvas tap to `Flow.endGame` while `state === "gameover"`. `#app` (not just the canvas) needs `touch-action: none` so strip drags don't scroll/zoom.
- Landscape is enforced by CSS only: `index.html` has a `#rotate` overlay shown by `@media (orientation: portrait)` in `public/style.css`; the overlay shows an animated beer bottle (`.rotate-bottle`) that tilts 0°→90° in a 2.6 s loop as the rotation hint. It reuses the DOS ship strip as a CSS sprite (`background: url("assets/enemies/ship.png") 0 0 / 960px 288px no-repeat` + `steps(10)` on `background-position`, `image-rendering: pixelated`, `prefers-reduced-motion: reduce` shows it static at 90°) — **the url must stay relative**: `public/style.css` is copied to the deploy root verbatim, so an absolute `/assets/...` would 404 under the `/last-eichhof/` base; the viewport meta disables zoom and `#app { touch-action: none }` (canvas too). `main.ts` sets `input.activePointers: 3` for simultaneous joystick + buttons. `#app` must **not** combine `height: 100dvh` with `display: flex`: on Chrome Android (esp. installed PWA) the container keeps the stale portrait height after rotation/address-bar change, so Phaser's FIT scale fills the width and overflows top/bottom. Use `#app { position: relative; width: 100vw; height: 100vh; height: 100svh }` + a full-size `#game-container` and let Phaser's `autoCenter: CENTER_BOTH` center the canvas (no flex). `100svh` (small viewport) is required on iOS Safari, where `100vh` is the large viewport and pushes the canvas bottom behind the toolbar after a portrait→landscape rotation; `main.ts` `fitViewport()` patches iOS < 15.4 (no `svh`) from `visualViewport`.
- Fullscreen toggle lives in `src/game/input/fullscreen.ts`: `toggleFullscreen(scene)` only (no separate button; `createFullscreenButton` was removed). It is a native menu entry (`Menu.rebuild` builds a `fullscreenEntry` `Item` with a dynamic `FULLSCREEN`/`EXIT FULLSCREEN` label), inserted above `OPTIONS` on the start screen and above `END GAME` in the pause overlay (so `END GAME` stays last); it is omitted entirely when `scale.fullscreen.available` is false (iPhone Safari) so there is never a dead entry. The entry sets `Item.pointerUp: true` so `addItems` binds `pointerup` instead of `pointerdown` — fullscreen requests must come from a user gesture and mobile browsers reject `pointerdown`. `Menu` re-renders on `Scale.Events.ENTER_FULLSCREEN`/`LEAVE_FULLSCREEN` to flip the label. `main.ts` sets `fullscreenTarget: "app"` so the `#app` container (canvas + `#rotate` overlay) goes fullscreen instead of Phaser wrapping the canvas in its own div.
- Audio is both sampled and synthesized. Extracted original DOS samples (`public/assets/sounds/*.ogg`, manifest `src/game/data/sounds.ts`) play through `Samples` (wraps Phaser's sound manager: `play`/`loop`/`setLevel`); `Synth` keeps Web Audio fallbacks where the original has none (player laser, hit, UI blips), and `Music` plays the `TITLE`/`GAME` synth patterns for menu/scores/game (the original `TITLE.SND`/`HS.SND` are copyright-protected, so `scripts/extract-sounds.mjs` skips them and the two OGGs are `.gitignore`d — do not re-add them). `Sound` is a namespace export; guard `manager instanceof Sound.WebAudioSoundManager` and use `manager.context`/`.destination`. `Samples`/`Synth`/`Music` no-op when the manager is HTML5/NoAudio.
- Web Audio context starts suspended; `Music.tick` must bail while `!synth.running` and resync `nextTime` when it lags `ctx.currentTime` (first gesture unlocks playback).
- Vite 8 / rolldown requires `build.rollupOptions.output.manualChunks` as a **function**, not an object map.
- `base` in `vite/config.*.mjs` must match the deploy directory (`scripts/deploy.sh` rsync to `html/last-eichhof/`, so base is `/last-eichhof/`). A mismatch makes the built CSS/JS 404, which leaves the raw `#rotate` overlay visible and the game blank.
- `vite/config.prod.mjs` sets `build.outDir: "../dist"`: vite's `root` is `src`, so the default `dist` would land in `src/dist` (untracked, unlinted, and not what `scripts/deploy.sh` rsyncs). Keep it pointed at the repo-root `dist` that `.gitignore` ignores.
- Pure logic also gets a `run*SelfCheck()` (assert-based) called from `Boot.create()` behind `import.meta.env.DEV` (stripped from production builds), plus a vitest case calling it (`expect(() => run…()).not.toThrow()`); keep it passing (vitest cannot reach the Phaser scenes).
- `biome check --write` may reorder imports; run it before `tsc`/`build`.
- No `Math.random` (Sonar S2245): visuals that must be reproducible (star fields) use a seeded `Phaser.Math.RandomDataGenerator`; audio noise uses `crypto.getRandomValues` (max 65536 bytes per call: fill in chunks).
- `ScenePlugin.restart()`/`start()` with no data keep the previous scene data; pass explicit data (`restart({ pause: false })`) to reset `init()`.
- Scenes render in config-list order (`[Boot, Menu, Shop, Game]`), so `Game` draws **over** an overlay launched with `scene.launch("Menu")`; call `scene.bringToTop("Menu")` when launching the pause overlay or it stays hidden behind the game.
- Phaser 4 removed the `setTintFill(color)` argument: use `setTint(color).setTintMode(TintModes.FILL)` (import `TintModes` from `phaser`).
- `Menu` and `Shop` treat Enter and Space as the same confirm key; keep both wired when adding menus. Menu/Shop list items are also pointer-clickable (`setInteractive` + `pointerdown`); in `Menu` that calls `activateEntry(entry)`, which selects the entry, plays the confirm sound and activates it. In `Menu`, each entry also has an icon (`UI_ICONS`, scaled to 26 px) and an invisible interactive `Zone` (depth 12) as its pointer target; `refresh()` draws a rounded gold highlight bar behind the cursor entry (faint for hover) via the shared `highlight` `Graphics` (depth 9), and dims the non-selected icons. `Menu`'s score tabs and footer (back) are clickable too, as is the `Game` game-over `pointerdown`.
- `Menu` navigation is **row-based**: entries live in `this.rows` (`Entry[][]`), with `this.row`/`this.col` as the cursor. `addItems(defs, y, step)` makes one row per item (vertical menu), `addActionRow`/`addLinkGroup` make horizontal rows. Up/down move between rows (clamped, no wrap) keeping the column when possible; left/right cycle a value item (`cycle`) or move within a multi-entry row. Vertical lists are icon + left-aligned label, auto-centred as a block, with a full-width pointer `Zone`; horizontal rows use `layoutEntries` to centre icon+label items and size each `Zone` to its content. `refresh()` paints the cursor entry gold and brightens its icon, the hovered entry lighter, the rest dim. A `panel` `Graphics` (depth -5) draws a translucent card auto-fitted to the content bounds. Every entry is keyboard- and mouse-reachable. `Menu` modes: `menu` (start screen with the `INSTALL APP` / `SHARE` / `CONTACT` action row and the footer link groups), `options`, `scores`, `pause`, `install`. `INSTALL APP` is omitted when already running standalone (`isInstalled()`: `matchMedia("(display-mode: standalone)")` or iOS `navigator.standalone`); it calls `hasInstallPrompt()`/`promptInstall()` from `src/game/pwa.ts` (captures `beforeinstallprompt`, `preventDefault` + deferred `prompt()`), else opens the `"install"` mode screen with the Android/iPhone instructions (BACK item, ESC returns). `SHARE` uses `navigator.share` (title + `location.href`), else `navigator.clipboard.writeText` and swaps its label to `LINK COPIED` for 1.5 s. `CONTACT` opens `https://entorb.net/contact.php?origin=last-eichhof`.
- Enemy/ship/explosion art and the per-level enemy rosters are extracted from `original_game/beer_exe/BEER.DAT` by `node scripts/extract-sprites.mjs` (see [docs/beer_dat.md](docs/beer_dat.md)). It writes `public/assets/enemies/<key>.png` (horizontal animation strips, 3× nearest-neighbor) + a `contact.html` sheet, and regenerates `src/game/data/enemySprites.ts` (`SPRITE_SHEETS`) and `src/game/data/foeRosters.ts` (`FoeKind`/`FOES`/`ROSTERS`). Never hand-edit those generated files — edit `scripts/enemy-map.json` or the DOS data and re-run. `enemy-map.json` also has a `weaponSprites` map (`<weapon id>` → `WEAPONS.SLI` sprite index) which emits all 9 DOS shop weapons as `wpn-<id>` sheets, and a `shotSprites` list (indices 9–21) which emits the DOS projectile art as `shot-<n>` sheets (`Boot` has a procedural fallback for any weapon id missing from `SPRITE_SHEETS`, currently unused). `Boot.preload()` loads each sheet via `load.spritesheet`; `Boot.create()` registers an anim per sheet (`repeat: -1`, except `explosion` which is `repeat: 0`). Phaser `GameObjects.Sprite` is not a subclass of `GameObjects.Image`; animated objects (ship, enemies, explosions, weapon mounts) must be typed/created as `Sprite` (`add.sprite`), and `overlap()` takes `Image | Sprite`.
- The readable C port of the original at `original_game/allegro_src/lastbeer-2.0/` (Gavin Smith 2014, GPL) is the authoritative reference; porting/verification notes live in [docs/allegro_src.md](docs/allegro_src.md). Verified semantics to keep: `nbigboss` counts `.dsc`-scheduled `FOE_ENDLEVEL` boss spawns (level 4 has no such foe — web's `roleFor` `score < 0 → boss` heuristic is intentional); homing (`nearestEnemy`) must skip `invincible`/`transparent` foes; `FOES[].stopcount` foes (flag 0x08: l1-f16, l2-f2, l2-f59, l3-f5) must freeze `spawnWaves` while alive; the whole world incl. firing runs during shield (`updateShield` calls `updatePlay`).
- Original sound FX/music are extracted from `original_game/beer_exe/BEER.DAT` by `node scripts/extract-sounds.mjs` (see [docs/beer_dat.md](docs/beer_dat.md)). It decodes `.SND` (single `sndstrc` or library; 8-bit PCM or 4-bit Creative ADPCM `0x75`), encodes OGG Vorbis via `ffmpeg-static`, writes `public/assets/sounds/<key>.ogg` + `audition.html`, and regenerates `src/game/data/sounds.ts` (`SOUNDS` manifest + `LEVEL_CUES`). Never hand-edit `sounds.ts` — re-run the script. `Boot.preload()` loads every manifest entry with `load.audio`; `Samples` maps game events to keys (`enemyShot`/`explosion`/`bossExplosion`/`cue` are per-level from `LEVEL_CUES`). `biome` ignores the generated `audition.html`.
- Two graphics skins, selected by `Settings.graphics` (`"modern"` default, `"original"` for the DOS art). Keys are canonical DOS names; the modern twin lives under the `m-` prefix and `texKey(key)` resolves the active one (`src/game/art/skin.ts`). `texKey` passes unknown keys through unchanged, so `stars-*` and `ui-*` (mode-independent) never get a prefix. **Every** world texture must go through `texKey` — ship, foes, path `sprite` events, shots, mounts, `pellet`, `explosion` — or a mode switch leaves stale art on screen.
  - `original` = the extracted DOS sheets (plain texture/animation keys), plus procedural `cork` (fallback when a `shot-<n>` sheet is missing), `pellet` (enemy line shots) and `stars-*`. The UI icons (`src/game/art/uiIcons.ts`, generated in `Boot.create()` via `generateUiIcons`) are always procedural and mode-independent.
  - `modern` = `src/game/art/{vector,foeArt,rigArt,skin}.ts`: Canvas2D generators (gradients/glows/rounded shapes, `wordmark` for the brand plates). **Never use `Graphics.generateTexture` for it** — Phaser 4 documents that gradients are dropped from the baked texture (`phaser.d.ts` "Graphics features, such as `fillGradientStyle`, will not appear on the resulting texture"), so the modern skin must be painted into a `CanvasTexture`. Frame geometry matches the DOS sheet exactly (same `frameWidth`/`frameHeight`/`frames`), so `displayWidth`-based collision, the shop footprints and `runWeaponsSelfCheck`'s `mount size` assert all stay valid.
  - `applySkin(scene)` paints **both** key spaces once per page (a `generated` guard) and then only re-points `activeMode`; it is called at the top of `Boot`/`Game`/`Shop` `create()`. Because both spaces exist, a mid-game switch is just `Game.reskin()` (on `Scenes.Events.RESUME`), which re-textures the live ship/foes/shots/explosions and rebuilds mounts — never regenerate a texture a live sprite already references, or the paused scene breaks. The DOS PNGs are always preloaded so a switch never has to load mid-frame.
  - Foe art is one parametric table: `FOE_ART` (84 `l<n>-s<m>` keys → `{art, motion, glass, accent, word}`) over ~29 scale-agnostic generators in `foeArt.ts`, plus `FOE_ASPECT` (natural width/length per subject). `motion: "spin"` (default) rotates the subject inside the frame, so a spinning bottle must be drawn *tall* (`subjectSize` in `skin.ts` applies `FOE_ASPECT`) — stretching it to a wide frame turns the strip into a smear. `runModernSkinSelfCheck()` asserts every sheet/texture/mount/shot has modern art and that the table is exactly 84 + 26 entries.
  - `src/skins.html` + `src/skins.ts` are a dev-only inspector (`/last-eichhof/skins.html` under `pnpm dev`, not in the build) listing every sheet's DOS PNG next to the modern art. It calls the same `drawModernSheet()` the game uses, so it cannot drift. `knip.json` needs `src/skins.ts` in `entry`.
- `CanvasTexture` frames: `createCanvas` gives only `__BASE`; call `tex.add(name, 0, x, y, w, h)` for each frame and `tex.refresh()`. The first added frame becomes `firstFrame`, so a frame-less `add.image`/`add.sprite` shows frame 0 (not the whole atlas).
- SonarCloud findings are pulled into `tmp/sonar.json`; fix every issue. Recurring rules:
  - `Number.parseInt`/`Number.parseFloat` over the globals (`S7773`); prefer `for...of` over an index `for` when the index is unused (`S4138`).
  - `String#codePointAt` over `charCodeAt` (`S7758`).
  - Mark fields only assigned in the constructor `readonly` (`S2933`) — includes constructor parameter properties (`private readonly synth: Synth`).
  - No nested ternaries (`S3358`); use `if`/`else` or a `switch`. Clamps use `Math.min`/`Math.max` (`S7766`).
  - Membership tests use a `Set` + `.has()`, not `Array#includes` (`S7776`).
  - Don't call `Array#push()` multiple times in one function (`S7778`); build one array literal (conditional spread for optional entries).
  - High cognitive complexity (`S3776`, threshold 15): split the function into small extracted private methods/helpers per concern (one loop/switch each), not `// biome-ignore` — see `src/game/data/path.ts` `PathRunner.step*`, `Game.collide*`, `scripts/extract-sprites.mjs` `decodePath` for the pattern.
  - Don't wrap a promise chain in `try` when `.catch()` already handles rejection (`S4822`); guard a possibly-missing global with `globalThis.fetch?.(...)` (optional chaining short-circuits the whole chain).
  - `.sonarcloud.properties` holds `sonar.exclusions` (generated files) and `sonar.issue.ignore.multicriteria` for intentional deviations (none today). Add new suppressions there with a comment explaining why — never inline `NOSONAR`.
  - Do not disable pinch-zoom via the viewport meta (`user-scalable=no`, `maximum-scale`); the canvas already blocks it with `touch-action: none` (`public/style.css`).
