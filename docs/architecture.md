# Architecture

Detailed map of the codebase. Coding rules and check commands live in
[AGENTS.md](../AGENTS.md).

| Area           | Where / what                                                                 |
|----------------|------------------------------------------------------------------------------|
| Scenes         | `src/game/scenes/`: `Boot` (textures + self-checks → `Menu`), `Menu` (modes title/options/scores/pause/install; row-based cursor, icons + gold highlight bar + auto-fitted panel, all entries keyboard- and mouse-reachable; scores mode lists **every** game ever played and has `BY POINTS`/`BY DATE` sort tabs — left/right switches sort, up/down scrolls via `clampScroll`, Enter/Esc exits; pause overlay is `RESUME`/`AUTO-FIRE`/`MUSIC`/`END GAME`/`FULLSCREEN`; install mode shows the Android/iPhone "add to home screen" steps; the start screen has the action row `INSTALL APP`/`SHARE`/`CONTACT` plus footer link groups — `Original DOS game: Download SourceCode Wikipedia` and `This game's: Code` — plus "Global Games Played"), `Game` (gameplay; always-visible top-left `MENU` button opens the pause overlay, keyboard or touch), `Shop` (between levels; modes `shop` root categories → `weapons`/`upgrades`/`sell` submenus, `place`; ESC in a submenu returns to root, ESC in root continues) |
| PWA install    | `src/game/pwa.ts` exposes `captureInstallPrompt()` (called once from `src/main.ts`), `hasInstallPrompt()` and `promptInstall()`; it defers `beforeinstallprompt` so `Menu`'s `INSTALL APP` can trigger the native prompt, else the `install` info mode. Unit-tested in `src/game/pwa.test.ts`. `vite-plugin-pwa` builds the manifest/service worker in prod only |
| Level data     | `src/game/data/path.ts` (`PathRunner`, `pathFor(kind)`), `playfield.ts` (`PLAY {w:960,h:720,hud:48}`), `math.ts` (`clamp`); generated `FOES`/`FoeKind` live in `foeRosters.ts` |
| Levels         | `src/game/data/levels.ts`: `LEVELS[5]` built from generated `ROSTERS` (`{n,name,bg,starTint,bosses,checkpoints,bonusScore,bonusMoney,build()}`), `getLevel(n)`, `runLevelsSelfCheck()`. `bonusScore`/`bonusMoney` are the DOS `.DSC` values that `initlevel` adds at level start |
| Rosters        | `src/game/data/foeRosters.ts` (generated): web level *n* = DOS `LEVEL{n-1}`; one `FoeKind` (`l{level}-f{foe}`) per referenced non-projectile `.FOE` entry, shared texture `l{level}-s{sprite}`; `FOES[kind].path` is the replayed DOS `.FOE` path; `ROSTERS` carries the DOS `.TBL` spawn schedule (`at`=frames/20, coords ×3), `MARK` checkpoints, boss count and the `.DSC` `bonusScore`/`bonusMoney`. Foe shields and scores are the raw signed `.FOE` values — bosses are negative and subtract on death, shields are used as-is (no clamp/scale) |
| Weapons        | `src/game/data/weapons.ts`: `WEAPONS` = the 9 DOS arms only (lager starter + stange/pony/barbara/dunkel/can33/chuebeli/pokal/kanone; emitter lists + `period`/`power`/`kind`, `w`/`h` = real sprite footprint). Each fires its DOS shot script (WPNPATH.C): pony = Pony Reflector, barbara = V-shot, dunkel = homing, can33 = side shots, chuebeli = Humpe back shot, pokal = burst, kanone = cannon. DOS delta ×60 px/s, DOS reload `period+1` frames, non-straight `life` = DOS path length / 20 Hz. Each emitter carries its DOS `shotstrc` `shotx`/`shoty` (×3) as `ox`/`oy` and its `sprite` as `shot-<n>` (animated shots play via `anims`, `Game.makeShot` uses `add.sprite`). `weaponStats` shows the main emitter's power only (sub-shots excluded). Costs are the DOS `.WPN` values (240–540, upgrades 200/30). `UPGRADES` names are the DOS `.WPN` strings ("I WANT TO BE FAST", "BONUS GUTTERE"). `UPGRADES`, `moneyForLevel`, `GRID=12` (DOS 4 px ×3), `snap`/`canPlace`, `runWeaponsSelfCheck()` (asserts exactly 9 weapons, `w`/`h` match the extracted `wpn-<id>` sheet, and every shot `sprite` exists). `moneyForLevel(scoreDelta) = trunc((scoreDelta + 1500) / 2500) * 5` matches `weaponmanager` (trunc, not floor — deltas can be negative) |
| Run state      | `src/game/data/run.ts`: in-memory `Run` (level, money, score, lives, speedUps, godMode, loadout); `newRun`/`getRun`/`endRun`/`shipSpeed`. `newRun()` resets every per-game value (money/score/level/lives/speedups/god mode/loadout), so a new game never inherits the previous run — asserted by `runRunSelfCheck()`/`run.test.ts`. DOS ship speed: base 240 px/s (`STARTSHIPSPEED` 4 px/frame ×60), speedup +120 (`MAXSHIPSPEED` 8 = max 2) |
| Persistence    | `src/game/data/store.ts`: settings + results in `localStorage` (`eichhof.settings`, `eichhof.results`), all wrapped in try/catch. Results are uncapped ("every game ever played"); `sortResults(results, "points" | "date")` drives the scores screen (`points` = score desc, ties to the older run; `date` = newest first). `Settings.music` (OPTIONS + pause overlay) toggles the synth music only — SFX/samples stay on |
| Scene flow     | `src/game/flow.ts` holds every transition as a pure function taking a `SceneSwitcher` (the scenes pass `this.scene`; tests pass a recorder): `startNewGame`/`pauseGame`/`resumeGame`/`endGameAndShowScores`/`finishLevel`/`endGame`/`continueToNextLevel`. `Boot → Menu → Game ⇄ Shop → Menu`; win levels 1–4 → `Shop`, win level 5 → `Menu` (game complete), game-over/quit → `Menu`. `Menu` START GAME calls `newRun()` so a new game always starts at score 0; `Shop → Game` reuses the in-progress run. Every `start("Menu")` from `flow.ts` passes `{ pause: false }` (plus `scores: true` from pause END GAME): a bare `start` reuses the previous Menu data, so after a pause overlay (`{ pause: true }`) a game-over would reopen the Menu in pause mode over a stopped Game (black screen) |
| Difficulty     | `DIFFICULTY` in `store.ts`: easy/normal/hard → lives 5/4/3, foe speed 0.85/1/1.2 (lives seed `newRun`) |
| Mobile input   | `src/game/input/`: `controls.ts` (`resolveTouchControls`, `moveVector`, `stickFromForce`; pure, self-checked, tested) + `touchpad.ts` (on-screen d-pad for `Menu`/`Shop`) + `edgeStick.ts` (raw DOM pointer drag in the letterbox strips beside the canvas also steers). `Game` adds a floating `phaser4-rex-plugins` `VirtualJoyStick` (invisible `Zone` base) + auto-fire + an always-visible top-left `MENU` button (keyboard and touch); `Shop` place mode is drag-to-position. `Settings.controls` (auto/touch/keyboard, not exposed in OPTIONS) selects it; `Settings.autoFire` (OPTIONS and pause-overlay `AUTO-FIRE`, default off) makes the ship fire without holding SPACE (touch always fires); `Game` re-reads it on `Scenes.Events.RESUME` so toggling it while paused applies to the running game; landscape-only via the CSS `#rotate` overlay |
| Enemy art      | `scripts/extract-sprites.mjs` → `public/assets/enemies/<key>.png` (original DOS sprites, 3×) and generated `src/game/data/enemySprites.ts` (`SPRITE_SHEETS`) + `src/game/data/foeRosters.ts`; `Boot` loads/animates them. `WEAPONS.SLI` also yields the `wpn-<id>` mount sheets (see `enemy-map.json` `weaponSprites`) and the `shot-<n>` projectile sheets (`shotSprites`). Procedural in `Boot`: `cork` (fallback), `pellet`, `stars-far/near`, the 5 web-only `wpn-<id>` icons. `contact.html` is a dev aid |
| Audio          | `src/game/audio/`: `Samples` (plays extracted original `.ogg`s through Phaser's sound manager; `setLevel`), `Synth` (Web Audio SFX + fallbacks), `Music` (synth `TITLE` menu/scores + `GAME` pattern; `setEnabled(false)` silences it — `Boot` seeds it from `Settings.music` — and `setScene` re-plays the current scene when re-enabled; original `title`/`hs` samples are not shipped), singleton `initAudio`/`getSfx`/`getMusic`/`getSamples`; `runAudioSelfCheck()`/`runSoundsSelfCheck()` in `Boot` |
| Sound          | `scripts/extract-sounds.mjs` → `public/assets/sounds/<key>.ogg` (original DOS samples, OGG Vorbis) + generated `src/game/data/sounds.ts` (`SOUNDS`, `LEVEL_CUES`); `Boot` loads them, `Samples` plays them (`buy`/`sell` shop loops, `go`/`tod`, per-level `enemyShot`/`explosion`/`bossExplosion`/`cue`). Original `TITLE.SND`/`HS.SND` are copyright-protected and intentionally not shipped (`.gitignore`d) — menu/scores music is synth. `audition.html` is a dev aid |
| PWA            | `vite-plugin-pwa` in `vite/config.prod.mjs` only (`registerType: "autoUpdate"`, `injectRegister: "auto"` so no `virtual:pwa-register` import → knip-clean). Workbox precaches the whole game (`globPatterns` incl. `png`/`ogg`, `maximumFileSizeToCacheInBytes` 6 MB for the phaser chunk, `navigateFallback: "index.html"`); `devOptions.enabled: false`, so test offline with `pnpm run build && pnpm run preview` (base `/last-eichhof/` is auto-applied to manifest `scope`/`start_url`/icon paths). Icons are generated by `scripts/gen-icons.mjs` (crops `public/assets/enemies/ship.png` frame 0, shares `scripts/lib/png.mjs` with `extract-sprites.mjs`) into `public/icons/*` + `public/favicon.png`; they are committed and only regenerated by `pnpm run icons` (never on build). Manifest/meta live in `src/index.html`. `cspell.config.yaml` ignores `pnpm-lock.yaml` (dependency names would otherwise flood the word list) |

- HUD occupies top `PLAY.hud` (48px); play area is below it.
- Scoring/money follow DOS exactly: `Game.resetLevel` records `levelStartScore` **before** adding the `.DSC` `bonusScore`/`bonusMoney` (DOS `initlevel`), `killEnemy` adds the raw signed `FOES[kind].score` (bosses are negative), and `checkWin` converts `moneyForLevel(score - levelStartScore)` into money on every level except the last (DOS skips `weaponmanager` after level 5). There is no flat per-level money bonus and no `scoreScale`.
- Game states: `shield → play → dead → win | gameover`; `ESC`/`MENU` pauses (`scene.pause`) and launches `Menu` with `{ pause: true }` (RESUME / AUTO-FIRE / MUSIC / END GAME; END GAME calls `Game.abortGame()` to record the score + `endRun()` and reopens `Menu` with `{ scores: true }`).
- Music is scene-driven via `getMusic().setScene("menu"|"scores"|"game"|"shop")`; menu/scores always use the synth `TITLE` pattern (original samples not shipped); `resumeGame()` restores game music. `Shop` calls `setScene("shop")` (stops the `GAME` synth) then loops `buy`/`sell` samples. `Boot` sets `sound.volume = 0.8`.
- Weapons fire simultaneously from the run loadout, each on its own `period` cooldown; shots carry `power`, plus `homing`/`reflect` behaviors.
- `Emitter.release` (`weapons.ts`) spawns sub-shots mid-flight (`after` seconds) at the parent's position with the parent tint; `Game.releaseShots()` fires once and clears the release. Pokal bursts into 4 diagonals, Pony Reflector releases a second bouncing shot.
- `PathRunner` (`level1.ts`) path commands: `go`/`line`/`home`/`wait`/`mark`/`loop`/`cycle(times)`/`spawn(kind)`/`sprite(texture)`/`release(kind,x,y)`/`shot(speed)`. `spawn`/`sprite`/`release`/`shot` are instantaneous and pushed to `runner.events`; `Game.updateEnemies` drains them. `mark` also records the position and `loop`/`cycle` reset `pos` to it (DOS `CYCLE` returns the object to the `MARK` position). Foe flags `invincible` (blocks but unharmed) / `transparent` (shots pass through) live on `FoeSpec` and are honored in `Game.collide()`.
- Enemy movement is **the original DOS path**, not an archetype. `FOES[kind].path` is generated by `scripts/extract-sprites.mjs` from each `.FOE` path: runs of identical `(dx,dy)` frames merge into one `go` (coords ×3, `speed = |delta|*60` web px/s so one 20 Hz frame is preserved), plus `mark`/`loop`/`sprite`/`release`/`shot`. `pathFor(kind)` (`level1.ts`) returns that real path for **every** foe with one — bosses, minibosses and `invincible`/`transparent` foes included (e.g. level 2's invincible miniboss `l1-f34` must still descend/release/retreat, not take the generic exit). The `weave`/`diver`/`zig`/`miniboss`/`boss`/`EXIT_PATH` archetypes remain only as a fallback for foes without a path. `Game.updateEnemies` destroys any foe whose path hits `END` (DOS `0x8000`); if it was a scheduled boss that reaches `END` un-killed it also decrements `bossesLeft`. Bosses are detected by `FOES[kind].role`, never by the string `"boss"`.
- Enemy fire **is** in the paths: a `RELEASE` (`0x8002`) whose target is a `FOE_LINE` (`0x20`) foe becomes a `shot(speed)` event; one whose target is a fightable minion becomes a `release(kind,x,y)` event. Both fire exactly when the path reaches the command and repeat on `loop`. Releases chain like DOS (a released minion may release its own), capped at `MAX_FOES` (26, DOS `MAXFOES`) so a looping foe cannot spawn without bound. `Game.spawnEnemyShot(x,y,speed)` mirrors DOS line mode: aim at the ship's position at release, velocity `speed*60` web px/s on the dominant axis (covers `max(|dx|,|dy|)` in `max/speed` ticks); the `pellet` texture is used as-is. Level 1 has no shooters; levels 2–5 are shot-heavy.
- Attack table (`Spawn.cmd`): generated `ROSTERS[].spawns` already interleave `.TBL` commands (`fieldOn`/`fieldOff`/`mark`) with foe spawns in one sorted queue. `Game.spawnWaves` toggles starfield scrolling (`fieldOn`) / stores a marker (no-op in the flat schedule). Use `fieldOff` before a boss and `fieldOn` shortly after.
- Paths are authored in DOS space and stay inside the play area (spawn coords are `.TBL` ×3, deltas ×3, so the original on-screen envelope is preserved). The DOS status bar sat at the **bottom** (`BARY`), so DOS `y=0` is the play-area top; the web HUD is at the top, so `Game.spawnWaves` adds `TOP` (`PLAY.hud`) to every spawn y. Without it, top-hovering bosses park behind the HUD (level 2's `l1-f37`). Off-screen culling uses the same envelope `levels.ts` asserts (`x < -PLAY.w` / `x > PLAY.w*2`), so foes that start just off-screen still fly in. Path-`END` destroys any foe (scheduled bosses decrement `bossesLeft`), and `checkWin` only needs `bossesLeft`, so a looping/un-killable foe can never soft-lock.
- Boss count is per level from the generated `ROSTERS` (`LevelDef.bosses`): `Game` tracks `bossesLeft` (not a bool) and wins on `bossesLeft <= 0` (DOS `nbigboss == 0`), even if released minions/chaff are still alive. All checkpoints sit before the first boss; on rewind `bossesLeft` is recomputed as bosses with `at > t` (they all re-spawn).
- Debug keys in `Game`: `J` jumps to the next checkpoint, or (once all are passed) to the boss and respawns it if missing; `G` toggles god mode (one-hit-kill enemies + money + player invulnerable). God mode lives on the `Run` (`godMode`), so it survives level transitions but `newRun()` resets it for a new game (its `GOD MODE` text is re-shown from `create`).
- Game feel (`Game.ts`): original `explosion` spritesheet animation (`spawnExplosion` plays the `explosion` anim once, `updateExplosions` fades it), white hit-flash on non-lethal enemy hits (`hitFlash` + `TintModes.FILL`), `cameras.main.shake` on player/boss hit, and alpha blink during the `shield` invincibility window.
- The HUD shows liters/level/lives; bottom-left shows the ship + a row of `wpn-<id>` loadout icons (no weapon names). Bought weapons are also mounted next to the ship (`Game.buildMounts`/`updateMounts`, skipping the starter lager = the ship itself), tracked to the ship each frame and hidden on death. Shop placement and the HUD/mounts all use the same `wpn-<id>` textures.
- Shop placement mirrors the DOS shop: the `wpn-<id>` sprite is drawn at native 3× size inside the 360×240 area, moved on the `GRID` (12 = DOS 4 px ×3) and kept inside with a 12 px margin; overlap uses the real footprints (`Weapon.w`/`h`) like DOS `crashtest`. The buy/sell lists show the weapon sprites next to the labels (`Shop.Item.icon`).
- Each level has a distinct background colour + star tint. Foe shields are the raw DOS `.FOE` values (bosses included) — no per-level bonus or HP scaling. `won` in results is true only on finishing level 5.
- Levels 2–5 define `checkpoints: number[]` (seconds, before the boss spawn). On death the game rewinds `levelTime`/`spawnIndex` to the last passed checkpoint and clears live enemies/shots; level 1 has none, so it continues in place. Self-check asserts checkpoints are sorted and pre-boss.
- Original DOS enemy fire = `FOERELEASEFOE` (`0x8002`) in a `.FOE` path, spawning a `FOE_LINE` (`0x20`) bullet (speed = that entry's `speed`) or a path foe (minion) at the parent position; the extractor replays it as a `shot`/`release` path event. `.FOE` layout: `n(2)` + packed far ptrs (unswizzle `((v>>12)&0xffff0)|(v&0xf)`, +2 base) + `foestrc {flags,shield,score,expl,sprite,speed,path[]}`; path commands `0x8000 END`, `0x8001 SPRITE(+1 word)`, `0x8002 RELEASE(+3 words)`, `0x8004 CYCLE`, `0x8005 MARK`, `0x8006 SOUND(+1 word)`, else a `(dx,dy)` pair = 1 frame @20 Hz. `LEVEL0..4` = levels 1..5; LEVEL0 (level 1) spawns no shooters, levels 2–5 are shot-heavy.
